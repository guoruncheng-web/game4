# 水果切切乐（Fruit Slasher）视听设计

## 1. 视觉目标

- **核心观感**：月夜竹林道场中的明快水果切割，安静背景与高饱和目标形成强对比。
- **关键词**：清爽、果汁感、东方夜色、强轮廓、短促爆发、手机可读。
- **画面基准**：`public/fruit-slasher/concepts/gameplay-concept-portrait-v2.png`。
- **原创边界**：使用原创标题、道场布局、图标和 UI，不复制《Fruit Ninja》的标志、菜单构图、刀具或专属素材。
- **实现路线**：背景、水果、炸弹和主要 UI 使用概念图派生的原创静态 PNG；Phaser 负责加载、缩放、物理、刀光、粒子和文字。小型通用粒子与空生命槽仍由 `Graphics.generateTexture()` 生成。

## 2. 竖屏构图

- 逻辑画布为 **540×960**，9:16 竖屏。
- 画面自上而下分为：HUD 安全区、主切割区、出生缓冲区。

| 区域 | Y 范围 | 用途 |
| --- | ---: | --- |
| 顶部安全区 | 0–112 | 分数、生命、暂停提示；不生成目标 |
| 主切割区 | 112–820 | 水果、炸弹、刀光与 Combo 的主要活动区域 |
| 出生缓冲区 | 820–960+ | 目标出生、桌面前景和手势安全区 |

- 核心目标出生在画布下方 `y = 990–1040`，进入画面前不可见。
- 水果飞行最高点应主要落在 `y = 220–590`，让纵向空间产生明显层次。
- 背景细节集中在两侧与上下边缘，中心 70% 保持低对比，不能干扰刀路判断。
- 桌面端仍渲染同一 9:16 画布，不另外设计横屏构图。

## 4. 画面分层

从后到前的固定深度顺序：

1. 夜空渐变与少量星点。
2. 月亮、远山和薄雾。
3. 中景道场屋檐与远竹。
4. 两侧近竹和灯笼。
5. 完整水果、炸弹。
6. 水果半块和果汁粒子。
7. 刀光。
8. 得分飘字与 Combo。
9. HUD、教学和暂停 UI。
10. 爆炸闪光、结算遮罩与结算卡片。

背景使用 `public/fruit-slasher/assets/backgrounds/dojo-night-v1.png`，启动时加载为单张静态纹理。

## 5. 背景规格

### 夜空与远景

- 使用 6–8 条横向色带模拟深蓝渐变，避免依赖 Canvas 渐变兼容细节。
- 星点最多 28 个，直径 1–2 px，透明度 `0.15–0.55`，不做高频闪烁。
- 月亮直径约 64 px，放在上半区偏侧位置，透明度约 `0.70`，不与 HUD 重叠。
- 远山使用 2–3 层不规则剪影，越远越蓝、越近越暗。

### 竹林与道场

- 两侧各 2–3 根竹竿作为竖向框景，宽 12–20 px，节点用较亮短横线表现。
- 竹叶只沿边缘出现，中心区域不伸入超过 48 px。
- 中景建筑只保留屋檐、窗格和暖灯矩形，不画复杂纹理。
- 底部木台高约 86 px，以 5–7 条木板分缝和少量结疤表现材质。

### 背景动效

- 远雾以 12–18 秒完成一次缓慢水平漂移，振幅不超过 24 px。
- 灯笼亮度在 `0.88–1.0` 之间轻微呼吸，周期约 2.4 秒。
- 星点不整体运动；最多 3 个星点做低频亮度变化。
- 背景动效在爆炸、暂停和页面失焦时必须同步停止。

## 6. 水果贴图

### 统一规格

- 每种水果生成一张完整贴图，以及左右或上下两个切开半块贴图。
- 完整水果贴图画布建议为 `104×104`，实际可见直径 64–86 px。
- 半块贴图建议为 `72×96`，切面朝向纹理内侧；场景中根据挥刀角度旋转。
- 轮廓至少包含底色、暗侧、亮侧高光和水果专属纹理四层。
- 高光统一位于左上，暗部位于右下，维持整体光源一致。
- 禁止写实噪点和细碎描边；在 360 px 宽的设备上缩放后仍须一眼可辨。

### 各水果轮廓

- **西瓜**：近圆形、最大体积；深浅绿色纵向条纹；切面有黑籽和浅色瓜皮圈。
- **橙子**：标准圆形；皮上少量浅色毛孔点；切面用 8 个扇形分瓣。
- **苹果**：上宽下窄的双弧轮廓；顶部短梗和单叶；切面有浅黄果肉与两粒籽。
- **猕猴桃**：棕色椭圆；外皮用短线表现绒感；切面为绿色放射纹和黑籽环。
- **草莓**：心形 / 锥形轮廓；顶部叶冠；黄籽沿表面均匀分布。

### 尺寸建议

| 水果 | 视觉直径 / 高度 | 判定视觉印象 |
| --- | ---: | --- |
| 西瓜 | 86 px | 最大、最好切 |
| 橙子 | 72 px | 标准圆形 |
| 苹果 | 74 px | 标准偏宽 |
| 猕猴桃 | 68 px | 最小圆形 |
| 草莓 | 68 px 高 | 窄而尖，判定不可过小 |

草莓的物理判定仍按产品文档的公平半径处理，不按尖角精确描边。

## 7. 切开表现

- 命中瞬间隐藏完整水果，并在同位置创建两个半块。
- 两半沿垂直于刀路的方向分别获得短促分离速度，初始间距为 4–8 px。
- 半块保留原水果的整体速度，再叠加 `70–120 px/s` 的分离速度与相反旋转。
- 切面始终比外皮亮一级，外沿增加 2 px 浅色高光，确保“切开”立即可见。
- 两半生成时使用 `scale 0.92 → 1.03 → 1.0` 的 90 ms 弹性，不做长时间慢动作。
- 普通命中允许 25–40 ms 的轻微时间缩放；连续命中时合并反馈，不能叠加成明显卡顿。

## 8. 果汁与碎屑

### 果汁粒子

- 每颗水果生成 8–14 个液滴，Combo 时总数封顶 42 个。
- 粒子使用 3 种尺寸：3、5、8 px；寿命 `260–520 ms`。
- 颜色取当前水果果肉色，并加入不超过 20% 的亮暗变化。
- 发射方向以刀路法线为主，混入约 ±35° 随机散射。
- 粒子受轻微重力影响，快速缩小并淡出。

### 背景溅痕

- 每次切中可留下 1 个低透明度椭圆溅痕，直径 24–50 px。
- 同屏溅痕最多 8 个，存在 1.8–3 秒后淡出。
- 溅痕位于目标层之后，不能遮挡炸弹轮廓。
- 低性能模式可完全关闭溅痕，只保留飞行粒子。

## 9. 炸弹

- 视觉直径约 76 px，与橙子接近但轮廓更紧实。
- 主体为近黑圆形 `#151A1D`，左上灰蓝高光，右下纯黑暗部。
- 外圈使用 3 px 暗红描边，中心放原创的红色菱形危险符号，不使用文字也能识别。
- 顶部短引线持续冒出 2–4 个橙黄火星；火星是炸弹唯一高频动效。
- 炸弹旋转速度应低于水果，危险符号保持大部分时间可读。
- 禁止让炸弹果汁化、卡通微笑或使用与水果相同的绿色叶片元素。

### 炸弹预警与爆炸

- 进入主切割区时播放一次很轻的引线声，不额外显示警告箭头。
- 刀光命中后先出现 120 ms 冻结：炸弹中心变白、外圈迅速放大。
- 随后产生一帧暖白核心、橙红冲击环、8–12 个暗色碎片和短促屏幕震动。
- 全屏闪光透明度不超过 `0.42`，持续不超过 90 ms，避免刺眼。
- 爆炸烟雾最多存在 650 ms，然后进入结算；不使用写实火焰或暴力碎片。

## 10. 刀光

- 刀光由最近 100–140 ms 的轨迹点组成，使用圆角折线。
- 外层宽 16 px、颜色 `#5DDCFF`、透明度 `0.20–0.45`。
- 中层宽 8 px、颜色 `#9CEBFF`、透明度 `0.65–0.90`。
- 核心宽 3 px、颜色 `#F4FFFF`、透明度 `0.95`。
- 轨迹从头到尾逐渐变细、变透明；最旧点优先移除。
- 快速挥刀时允许在刀头生成 1–2 个 2 px 星芒，慢速拖动不生成。
- 刀光不得保留成覆盖全屏的长尾，也不允许未按下时出现。

## 11. HUD 与文字

### 安全区

- HUD 顶边以运行时安全区为准，默认内边距 `24 px`。
- 分数位于左上，生命位于右上；两者不得侵入中央标题 / 提示区域。
- HUD 使用固定屏幕坐标，不随摄像机震动；爆炸时只震动世界层。

### 分数

- 字号 54–64 px，粗体，颜色 `#FFF0C8`，使用深蓝 4 px 描边或阴影。
- 不显示“分数”标签，减少视觉噪声。
- 加分时整体缩放至 1.08，再在 100 ms 内回到 1.0。

### 生命

- 使用 3 个 30 px 的红色迷你水果图标，间距 8 px。
- 失去生命时对应图标快速放大、裂开并变为 `#4C5660` 空槽。
- 空槽继续保留，玩家始终知道总生命上限。

### Combo 与飘字

- 普通 `+1` 飘字使用 22 px 米白色，向上移动 28 px 后在 360 ms 内消失。
- Combo 使用两行结构：上行 `3 FRUIT COMBO`，下行 `+6`；字号约 30 / 42 px。
- Combo 使用金色、深褐描边，并在不遮挡炸弹的位置动态偏移。
- Critical 使用 `CRITICAL +10`，颜色为亮橙，不与 Combo 共用同一行。
- 同屏飘字最多 6 组，超过时合并普通 `+1`，避免文字堆积。

### 字体

- 优先使用系统无衬线粗体：`Arial Rounded MT Bold`、`Noto Sans SC`、`sans-serif` 回退链。
- 标题可使用粗笔刷感，但运行时不引入网络字体；用粗体、轻微旋转和木牌承托获得主题感。
- 关键数字必须使用等宽数字或固定锚点，防止分数变化造成 HUD 左右跳动。

## 12. 菜单、暂停与结算

### 菜单

- 背景沿用游戏场景，但水果仅做 2–3 个低速装饰抛物线且不可切。
- 标题放在上半区木牌中，木牌宽约 390 px、高约 104 px。
- 主按钮不使用普通矩形按钮；使用一颗完整西瓜作为“滑动开始”的可切目标。
- 首次切开开始水果后，两个半块飞出，场景在 220 ms 内进入游戏。

### 暂停

- 世界层加 `#020711`、透明度 0.58 的遮罩。
- 中央显示“已暂停”和“点击继续”，不展示新的可切目标。

### 结算

- 使用居中的深蓝半透明卡片，宽约 430 px，圆角 24 px，暖金细边。
- 失败原因在顶部，分数为最大字号，最佳分和统计信息依次向下。
- 新纪录在分数上方显示金色印章形标记，并伴随 6–10 个纸屑粒子。
- “再来一局”使用可切水果入口，与菜单交互保持一致。

## 13. 动效节奏

| 事件 | 时长 | 视觉节奏 |
| --- | ---: | --- |
| 普通切中 | 90–180 ms | 瞬时切开、短高光、粒子爆开 |
| Combo 出现 | 420–650 ms | 弹入、停留、上浮淡出 |
| 漏切 | 280–420 ms | 红色边缘闪烁、生命裂开 |
| 炸弹命中冻结 | 120 ms | 所有世界对象短暂停住 |
| 爆炸主体 | 90–180 ms | 白芯、冲击环、震动 |
| 进入结算 | 350–500 ms | 世界变暗、卡片上移 |
| 新纪录 | 600–900 ms | 印章弹入、少量纸屑 |

- 同类反馈在高频触发时要合并或限流。
- 摄像机震动只用于炸弹；普通切水果不震屏，避免竖屏手持设备产生疲劳。
- 尊重系统“减少动态效果”偏好时，关闭顿帧、屏震和背景漂移，仅保留淡入淡出。

## 14. 音效设计

全部音效优先由 WebAudio 振荡器、噪声和包络实时合成，不依赖外部音频文件。

| 事件 | 声音组成 | 时长 / 音高 |
| --- | --- | --- |
| 挥刀 | 高通噪声快速扫频 | 70–110 ms，速度越快音高越高 |
| 切中 | 湿润噪声 + 短木质敲击 | 90–140 ms，不同水果轻微随机变调 |
| Combo | 2–4 个递升正弦 / 三角音 | 180–320 ms，数量越多终音越高 |
| Critical | 明亮钟声双音 | 220 ms，与普通 Combo 区分 |
| 漏切 | 下行三角波 + 低频闷响 | 260 ms，不做惊吓音 |
| 炸弹引线 | 稀疏噪声火花 | 每 300–500 ms 一次，音量很低 |
| 爆炸 | 低频正弦下坠 + 宽带噪声 | 450–650 ms，峰值需限幅 |
| 新纪录 | 三音上行短旋律 | 500–700 ms，明亮但不过度庆典化 |
| UI 开始 | 清脆木鱼 / 竹片音 | 100–160 ms |

### 混音规则

- 主输出峰值控制在约 `-3 dB`，爆炸不得削波。
- 同帧多个切中音效最多播放 3 个，其余合并为一个更饱满的切中声。
- 挥刀声设置 60 ms 冷却，避免每个指针采样点都触发。
- Combo 音优先级高于普通切中，爆炸优先级最高。
- 页面失焦、场景暂停或销毁时立即停止全部振荡器并释放 AudioContext 相关节点。
- 首次用户手势后再初始化 / 恢复声音，遵守浏览器自动播放限制。

## 16. 性能预算

- 同屏完整水果与炸弹最多 9 个。
- 半块最多 18 个，超出时优先回收最旧且已离开主切割区的对象。
- 活跃果汁粒子建议不超过 80 个，硬上限 120 个。
- 背景溅痕最多 8 个。
- 刀光轨迹点建议最多 18 个。
- 高频对象使用对象池，不能每帧持续创建新的纹理或 WebAudioContext。
- 所有静态纹理只在 Boot 阶段加载一次；生成纹理也只创建一次，重开不得重复加载或生成同名纹理。
- 低性能模式关闭背景溅痕、星点呼吸和半块弹性缩放，并将单次果汁粒子降至 5–8 个。

## 17. 可读性与无障碍

- 炸弹同时依靠黑色圆形、红色危险标记、火星和引线识别，不只依赖红色。
- 生命同时使用图形和位置变化；失去生命不能只改变颜色。
- 所有主要文字与背景对比度应达到清晰可读，文字至少带描边或暗色承托。
- 爆炸闪光不能使用纯白满屏持续显示。
- 提供静音状态；浏览器会话内记住静音选择。
- 触控目标最小可交互尺寸为 44×44 CSS px。

## 18. 美术验收标准
