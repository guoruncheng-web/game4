# 叠叠消(Triple Pile)视听设计

> 本文定「画面长什么样、声音是什么感觉」。玩法规则见 `DESIGN.md`,工程组织见 `ARCHITECTURE.md`。
>
> **本文不改动 `DESIGN.md` 的任何数值**:物理参数、相机机位、关卡表、槽位数全部照搬。

## 0. 美术路线:写实贴图低模,不是程序化几何

12 个食材是**用户提供的正视图渲染**(`assets/source/*-chroma.png`,1254² 品红抠像),
由 `tools/blender/triple-pile/build_models.py` 转成低模 + 贴图,产物是
`public/triple-pile/models/*.glb`(贴图内嵌,合计约 4.3MB,804 三角)。

### 0.1 这条路线取代了什么

初版设计走的是盒子里的老规矩 —— Three primitive 拼形状、顶点色上色、零外部文件,
并为此写了一整套**火锅配色论证**(明度阶梯、色相槽、图案特征三条通道)。
**那套论证现在作废了**,因为它的前提是「每个物件只有一个平面色块可用」。
写实贴图下每个食材自带独有的纹理与结构,识别通道宽得多。

这也直接解除了「MVP 只做 6 类」那条范围限制 —— 当时的理由之一正是
「火锅题材的色域只够 6 类」。现在是 **12 类全上**(`DESIGN.md` §5)。

### 0.2 建模脚本为什么能成立(三条性质,缺一条整套就垮)

1. **12 张源图都是正视图**。把图沿 -Z 平面投影回模型,等于把渲染反着贴回去,
   正面看过去和原图一致,不需要 UV 展开。
2. **模型的 XY 包围盒 == 贴图不透明像素的包围盒**,脚本强制保证。
   两者一旦对不上,超出图形轮廓的模型表面会采样到透明像素而**破洞**。
   所以模型尺寸不是手填的,是从图里量出来的;长条类(肥牛卷/蟹棒/香肠/腐竹卷)
   的朝向也是对 alpha 蒙版做 PCA 量出来的 —— 斜放的蟹棒因此能自动对上。
3. **模型本地 +Z 就是「正面」**。槽位里陈列时物件正面朝相机(`tray.ts` 的归位旋转),
   于是玩家在槽位里看到的**就是源图本身** —— 锅里认出来的和槽位里的完全对得上。
   这条是「拾取 → 归类」这个核心循环可读性的地基。

### 0.3 已知代价

- **侧面拉伸**。平面投影会把轮廓边缘那一排像素铺满垂直于 Z 的侧面
  (豆腐的顶面、玉米/藕片的侧壁最明显)。食材纹理本身杂乱,拉伸读起来就是「侧面」,
  在实际显示尺寸下可接受。想彻底解决要给侧面单独一套 UV 和贴图,不值这个成本。
- **背面是正面的镜像**。食物大多近似对称,翻过来看不出破绽。
- 这两条都在 62° 俯视 + 物件随机翻滚的前提下验收过(见 §0.4)。

### 0.4 改了建模脚本怎么验收

```bash
# 生成(在装了 Blender 的机器上,仓库根目录)
blender -b --python tools/blender/triple-pile/build_models.py

# 渲两张验收图
blender -b --python tools/blender/triple-pile/preview.py -- public/triple-pile/models /tmp
```

- `preview-front.png` 正视图,**应该和源图几乎一样**。不一样 = UV 投影或抠像出错。
- `preview-game.png` 按游戏的 62° 俯角渲,看侧面拉伸和轮廓破洞。

> **预览图上那几道细长条纹是 EEVEE 的渲染伪影,不是模型问题。**
> 已用 Workbench(纯光栅、无透明)渲过同一批模型:干净,无条纹;
> 顶点转储也确认包围盒正确、面数正确。Blender 5.x 的 EEVEE 去掉了 CLIP 混合模式,
> 透明材质只能走真半透明,这类条纹是它的已知表现。
> 游戏侧走的是 `alphaTest` 二值裁剪(见 §2.2),不经过半透明管线。

### 0.5 建模脚本里踩过的四个坑(改脚本前先读)

1. **图元自带一层 UV**。直接 `uv_layers.new()` 会建成第二层,而材质和 glTF 导出器用第一层 ——
   表现是贴图完全对不上、球面上出现破洞和锯齿环。必须先把自带的清掉。
2. **UV 球的极点正好落在正面中心**(极轴 = Z = 正面方向),极点处三角的 UV 退化成一个点,
   物件正中央会出现黑色风车状破面。改用 **icosphere**,没有极点。
3. **Blender 是 Z-up 而 glTF 是 Y-up**。建模和 UV 投影在 XY 平面做最直观,
   但直接导出会让物件在 Three 里「脸朝天」。导出前绕 X 转 -90°。
4. **抠像残留必须做 alpha bleed**。侧面拉伸会把轮廓边缘那排像素铺满整个面,
   边缘要是还留着品红,俯视时就是一道刺眼的粉色条纹。先把食材颜色向外扩散 18 圈再裁剪。

## 1. 视觉目标

- **核心观感**:一口暖铜锅俯视占据画面主体,锅里堆满写实、有体积感、
  **一眼能认出是什么**的食材。锅外的桌面是压暗的背景框,不抢戏。
- **关键词**:热气、油润、看得清、层层叠叠、拿走就塌。
- **绝不要**:高饱和背景、红汤(会和肥牛/香肠/蟹棒的红直接撞)、糖果渐变。

### 1.1 桌面是**屏幕空间背景图**,不是 3D 地面

素材 `assets/scene/tabletop.png` 是一张正俯视的照片式渲染(桌面木纹 + 四周的配菜碟、
蘸料碗、金针菇盘),中间留空给锅。产物 `public/triple-pile/scene/tabletop.jpg`(720×1560,82KB)。

**它当 CSS 背景铺在画布后面,不做成 3D 平面。** 理由是硬的:
素材是正俯视画的,而相机是 62° 斜俯视 —— 贴成 3D 地面会立刻暴露透视不一致。
当成背景板则没有这个问题,背景板没有透视,只有锅和食材是 3D 的,
这正是参考图那种「实拍桌面 + 立体锅」的合成感。

代价是背景不随相机变化(相机本来也全程不动,见 `DESIGN.md` §4.2),
以及画布必须 `alpha: true` 且不设 `scene.background`。

> 初版设计曾要求「桌面压到明度 0.24 并加暗角」,理由是本作没有阴影和后处理,
> 食材与背景的分离只能靠明度差。**用户提供的素材是亮木色(约 0.82),那条要求已作废。**
> 由此带来的新风险写在 §4.3 —— 不要为了「符合旧文档」去把这张图调暗。

## 2. 材质与渲染

### 2.1 光照

| 灯 | 类型 | 方向 | 强度 | 色 |
| --- | --- | --- | ---: | --- |
| Key | `DirectionalLight` | `(1.8, 6.0, 2.4)` | 0.78 | 暖橙白 `#FFE8CC` |
| Fill | `DirectionalLight` | `(-2.6, 1.2, -3.0)` | 0.24 | 冷紫 `#7A5A9A` |
| Ambient | `AmbientLight` | — | 0.30 | `#4A3020` |

Key 光靠近正上方,因为相机是俯视的 —— 侧打光会让朝上的面全部平掉。
贴图本身已经带了渲染时的明暗,所以这里的光只负责「让它属于这口锅」,不负责塑形。

### 2.2 食材材质:alphaTest,不走半透明

贴图是抠像来的,边缘有 alpha。**必须用 `alphaTest: 0.5` + `transparent: false`**,
不能按半透明渲染:场上峰值 120 个实例,半透明之间没有稳定的前后顺序,
表现是物件边缘互相穿插闪烁。alphaTest 是二值裁剪,正常写深度,和不透明物件一样排序。

同时 `side: FrontSide`(模型是闭合凸体,背面不需要画)、贴图 `anisotropy: 4`
(物件会翻滚,斜看时的清晰度差别很明显)。

### 2.3 锅体

锅体(内壁 + 锅底 + 锅沿 + 提手)是程序化的:一堆基本几何体 merge 成一个 mesh,
顶点色上色,`MeshLambertMaterial`。**这是场景里唯一还走程序化的部分** ——
桌面换成了背景图(§1.1),食材换成了 glb(§0)。

锅的视觉半径必须和物理的 24 段 collider 环内接半径对齐。视觉比碰撞大会出现
「明明还有空间却卡住」,反过来是「穿墙感」。

### 2.4 槽位条

底板是一张贴图(`slot-tray-chroma.png` 抠像而来 → `scene/tray.png`,1024×195)。
**7 个格子是画在图里的,不是代码摆出来的**,所以格子中心必须从图里量:

| 量出来的值 | 数 |
| --- | ---: |
| 内容框宽高比 | 5.213 |
| 首格中心(占板宽) | 0.0854 |
| 末格中心(占板宽) | 0.9130 |
| 单格宽度(占板宽) | 0.125 |
| 格子中心(占板高,自上而下) | 0.5646 |

这些数写在 `config.ts` 的 `TRAY.layout`。**换贴图必须重新量** ——
量错的表现是物件摆在格子外面,一眼看得出来但很难定位到是这里的问题。

槽位里的物件按**包围球归一化**缩放,不是统一系数:12 个模型尺寸差近 40%
(蟹棒 1.15 vs 鱼丸 0.84),乘同一个系数会让槽位里大小不一,数起来费劲。

底板 `depthWrite: false` 且 `renderOrder: 1`:食材是不透明的(alphaTest),先画完写好深度,
底板最后画靠深度测试被挡住。底板自己写深度的话会挡住紧贴在它前面的物件边缘。

## 3. 反馈(三个关键时刻)

### 3.1 拾取高亮

- `pointerdown` 命中时给一圈**描边**:同一 geometry 用 `side: BackSide` 外扩 1.06 再画一遍,
  颜色 `#FFD98A`。零贴图、零后处理、1 个 draw call。
- 同时放大到 1.06、上浮 0.05。
- **必须在 `pointerdown` 就给反馈,而判定在 `pointerup`**(`DESIGN.md` §13)。
  按下有反馈、松手才生效 —— 这是「滑开取消」能被玩家理解的前提。

### 3.2 飞行入槽(320ms)

- 二次贝塞尔,控制点在中点上方 +1.8。
- 同时用 `Quaternion.slerp` 旋转到**正面朝相机的标准姿态**。
  这个归位旋转是槽位可读性的全部来源 —— 玩家必须能一眼数清各类有几个,
  而正面朝相机时看到的就是源图(§0.2 第 3 条)。
- 缩放收到槽位尺寸,沿路撒 6 个尾迹粒子。

### 3.3 三消爆炸(140ms)

| 时间 | 表现 |
| ---: | --- |
| 0ms | 3 个物件同时**打白**:`color = 0x000000` + `emissive = 白` |
| 0–60ms | 缩放 1.0 → 1.25,emissive 衰减到 0.4 |
| 60–140ms | 缩放 1.25 → 0,喷 14 个主粒子(取该类型的 `color`)+ 6 个火花(加色) |
| 120ms | 分数飘字从槽位升起,400ms 淡出 |

**「打白」用 `color = 黑` + `emissive = 白`**:把 color 压到黑就把贴图彻底抹掉,
输出只剩纯白 emissive。这样爆炸效果对 12 个食材是同一个效果,**零特判** ——
不管它原本是绿的还是褐的。

粒子颜色取 `pieces.ts` 里每个类型的 `color` 字段(从各自贴图挑的主色),
这是那个字段唯一的用途 —— 模型的颜色全在贴图里,不经过代码。

## 4. 可读性风险(12 类之后的新问题)

老的风险是「平面色块的色域不够」,已经随路线变更消失。新的风险是另外两条:

### 4.1 三个浅米白的团块

**豆腐(方)、鱼丸(球)、饺子(半月)**都是浅米白。颜色帮不上忙,只能靠轮廓:
方 / 球 / 半月 三者差异足够大,但**在堆叠遮挡下只露出一角时会难分**。

缓解手段是关卡顺序:`TYPE_ORDER` 把这三样排在最后,
它们只在第 10 关之后才同时出现 —— 那时玩家已经玩了九关,认得住。

### 4.2 两组同色系

- **生菜 vs 白菜**:都是绿。靠轮廓(圆球 vs 长条)和白帮区分。
- **香肠 vs 蟹棒 vs 肥牛卷**:都是红白。香肠是纯红胶囊、蟹棒是斜向红白条、
  肥牛是竖直的卷 —— 三者的图案方向完全不同,这是主要分界。

**这两组的验收方式是灰度截图**:把游戏截图去色,如果还能分出来就算过。

### 4.3 浅色食材 vs 亮木色桌面(新增风险)

桌面底图是亮木色(明度约 0.82),而豆腐、鱼丸、饺子也在 0.85 上下。
**锅口以内不是问题** —— 锅是暖铜色(约 0.35),食材落在锅里,背景是锅不是桌面。
真正要盯的是两处:

1. **飞行途中**物件会掠过锅口以外的桌面区域,浅色食材在那一段会短暂地「糊」在背景上。
   飞行只有 320ms,且有描边和尾迹粒子帮忙,实测下来若仍难跟丢,给飞行中的物件加一圈描边。
2. **槽位条**里的浅色食材 —— 底板本身是浅灰白的,这一处对比最弱。
   底板贴图的格子是中灰(约 0.62),比食材暗一档,目前够用;不够的话把格子压深。

这两条都要在真机上看,不要靠静态推演下结论。

## 5. 音效

正式音效已改用 rFXGen 生成，成品位于 `public/triple-pile/assets/audio/`，原生预设和可复现构建器位于
`tools/audio/triple-pile/`。当前 `sfx.ts` 的 WebAudio 合成版本仍作为运行时原型；接入 WAV 时继续复用
全站音量键 `game-box-muted` / `game-box-volume`。

| 事件 | 音色 | 时长 |
| --- | --- | --- |
| 拾取 | 短促木质「笃」 | 85ms |
| 入槽 | 轻脆「嗒」 | 51ms |
| 三消 | 上行三音 + 尾部白噪爆音 | 257ms |
| 塌落 | 低频闷响 + 噪声,运行时音量随附近物件数缩放 | 201ms |
| 道具 | 移出 / 凑齐 / 打乱三种独立音色 | 118–323ms |
| 槽位告急(占 6 格) | 低频脉冲,每 800ms 一次 | — |
| 倒计时 | 短 tick；归零为低频重音 | 20 / 312ms |
| UI | 点击、返回、暂停、继续、提示、无效操作 | 35–135ms |
| 失败 / 通关 | 下行三音 / 上行五音琶音 | 827 / 763ms |

**「槽位告急」是唯一的听觉预警,它必须存在**:玩家的视线全程在锅里,不会一直盯着槽位条,
而「占到 6 格」需要一个不占视线的通道来告知。同时槽位底板转警示色。

## 6. 验收

1. `preview-front.png` 与 12 张源图几乎一致(§0.4)。
2. 12 类物件在**任意朝向**下都能辨认,包括完全背对相机时。
3. 灰度截图下,§4 那两组同色系仍可区分。
4. 轮廓上没有品红镶边(alpha bleed 生效,§0.5 第 4 条)。
5. 物件边缘不出现互相穿插闪烁(alphaTest 生效,§2.2)。
6. 桌面明度在 0.22–0.28,锅口内外有明确的明度断层。
7. 满场 120 个物件时,描边、飞行、爆炸三处反馈不掉帧。
