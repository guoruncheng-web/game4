# 投影拼合（Shadowcast）产品设计

## 1. 产品定位

- **类型**：单人空间推理益智 / 限时接力制。
- **平台**：手机竖屏浏览器为主，桌面浏览器使用居中的竖屏画布（540×960 逻辑分辨率）。
- **渲染**：**Three.js + 正交相机**，不使用 Phaser。无光照、无阴影贴图、无后处理、无外部资源文件。
- **目标时长**：单局 2–4 分钟（接力模式解开 8–15 题），首次游玩 10 秒内理解规则。
- **核心体验**：把一团乱七八糟的方块转到某个角度，忽然「咔」地看懂了 —— **顿悟**（MDA 美学中的 Discovery + Challenge），而不是手速。
- **在游戏盒子里的定位**：现有三款（star-runner 跳跃、fruit-slasher 挥砍、neon-strike 射击）全部是反射弧动作类。Shadowcast 是盒子里**第一款「脑子要转过来」的游戏**，也是第一款真 3D。它的存在价值就是把品类版图从「三个动作」扩成「三个动作 + 一个思考」。
- **设计边界**：不做账号、道具、养成、手工关卡、联网排行、付费。

## 2. 命名与标识

- **中文名**：投影拼合
- **英文名**：Shadowcast
- **slug**：`shadowcast`
- **一句话介绍**：转动一团方块，让它的影子拼成指定的形状。
- **卡片 tagline**（写进 registry）：`真 3D 空间推理 · 无限题目 · 90 秒接力`
- **controls**：`拖动旋转 · 方向键微调 · 空格定形`
- **持久化键**：`shadowcast-best`（单个 JSON 字符串，见 §11.4）

## 3. 核心循环

### 微循环（约 5–20 秒，一次「转-读-判断」）

1. 屏幕上半区悬着一团 4–9 个方块组成的连通体，下半区是一个对照框：**灰色实心 = 目标剪影**，**青色半透明 = 当前剪影**，重合部分显示为白色。
2. 玩家拖屏旋转方块团。当前剪影实时跟着变。
3. 玩家松手观察：重合区域变多了还是变少了？往哪个方向再转？
4. 接近正确时，剪影边缘开始发光、提示音音高上升、定形按钮开始脉冲。
5. 玩家按「定形」确认。

### 中循环（一局 2–4 分钟）

**接力模式**：初始 90 秒。解开一题 +10~14 秒（越往后给得越少），定形判错 -3 秒。时间归零 → 结算。分数 = 解题数。

### 宏循环（跨局）

- 破本地最高解题数记录。
- 可感知的能力成长：新玩家要靠「六面穷举」，熟练玩家会先转到能看清结构的视角再一步到位。这个差距是本作最主要的掌握感来源。
- 题目程序化无限生成，永远不会「打完了」。

## 4. 模式结构

**刻意只做两个模式，且不做难度档选择菜单。**

### 4.1 接力（Relay）—— 主模式

| 项 | 值 |
| --- | --- |
| 初始时间 | 90 秒 |
| 解题奖励 | 按难度档递减，14 / 13 / 12 / 11 / 10 秒（见 §6 难度表） |
| 判错惩罚 | -3 秒，且定形按钮冷却 1.2 秒 |
| 结束条件 | 剩余时间 ≤ 0 |
| 记分 | 解题数（主）；同解题数时比总用时（越短越好） |

### 4.2 禅意（Zen）—— 次模式，MVP 内

无计时、无惩罚、无奖励，连续出题，难度仍随解题数递增。记录「本局平均每题用时」。

**为什么它属于 MVP**：复用同一套关卡与判定逻辑，增量约 40 行；而思考类游戏被倒计时追赶会直接赶走一部分受众（自我决定论里的自主性需求）。这是本作性价比最高的一个模式。

### 4.3 为什么不做三档难度菜单

neon-strike / fruit-slasher 的三档难度是有意义的，因为它们的难度是「敌人多快多硬」这种连续量。Shadowcast 的难度已经**内生于题目序号**（方块数、朝向池、解数），再叠一个正交的难度档会让配平矩阵翻三倍；而且新玩家在开局根本无法判断自己的空间能力属于哪一档，这个选择是假的。**难度用曲线表达，不用菜单表达。**

## 5. 场景布局与投影规格

### 5.1 屏幕分区（540×960 逻辑像素，y 向下）

| 区域 | y 范围 | 内容 |
| --- | --- | --- |
| HUD 条 | 0–90 | 左：题号；中：时间条 + 秒数；右：本局最佳/记录 |
| **旋转区** | 90–640 | 3D 方块团。**只有这个区域内的指针按下才会开始旋转** |
| **对照框** | 660–880 | 240×220 居中，目标剪影 + 当前剪影叠加 |
| 操作条 | 880–960 | 「定形」按钮（宽 300、高 64、居中），右侧小按钮：暂停 |

对照框放在拇指上方、旋转区下方，是为了让「我转的手」和「我看的眼」不互相遮挡 —— 手机上手指会盖住旋转区下沿，所以旋转区底部 60px 视为「可能被遮挡」，方块团的包围球不得侵入。

### 5.2 投影规格（这一节决定判定是否公平，必须严格照做）

- **正交相机**，看向 -Z，`up = (0,1,0)`，位置 `(0,0,10)`，`near=0.1 / far=30`。
- **物体永远居中于原点，不允许玩家平移和缩放。** 缩放/平移会引入尺度与位置不变性 → 多解爆炸。
- 单位方块边长 = 1，格点为 3×3×3，坐标 ∈ {-1,0,1}。整个形状的**几何中心在生成后被平移到原点**（用格点包围盒中心，不是质心 —— 质心会让旋转看起来偏心）。
- 3×3×3 的外接球半径 = √3 × 1.5 ≈ 2.598。**正交相机视口半宽/半高取 2.9**，留 11% 余量。任何朝向下形状都不会被裁切。这是最容易做砸的一个数：视口取小了，某些角度下剪影被切边，IoU 判定直接失真。
- **剪影 = 当前视角的轮廓**，投影方向就是相机方向。绝不要设计成「从上往下投的影子」—— 那要求玩家做二次心智旋转，规则的可读性会瞬间崩掉。
- 剪影位图分辨率 **64×64**，与 2.9 半宽的视口一一对应（1 像素 ≈ 0.0906 世界单位）。

## 6. 难度曲线

难度按**本局已解题数**推进，与时间无关。

| 档 | 题号 | 方块数 N | 答案朝向池 | 允许解数 S | 剪影孔洞 | 解题奖励 |
| --- | --- | --- | --- | --- | --- | ---: |
| 入门 | 1–2 | 4 | 6 个正面轴向（屏幕内旋转不计） | 3–8 | 0 | +14s |
| 基础 | 3–5 | 5–6 | 24 个轴对齐朝向 | 2–5 | ≤1 | +13s |
| 进阶 | 6–9 | 6–7 | 24 轴对齐 + 8 个绕 Y 轴 45° | 1–3 | ≤1 | +12s |
| 挑战 | 10–14 | 7–8 | 上一档 + 4 个等距朝向（俯角 ≈35.26°） | 1–2 | ≤1 | +11s |
| 大师 | 15+ | 8–9 | 全池（40 个） | 1 | ≤1 | +10s |

**每档旋钮的意义**：

- **方块数 N**：直接决定剪影的信息量。N=4 时剪影是个一眼能认的字母形；N=9 时剪影往往是个不规则团块，必须靠推理。
- **答案朝向池**：入门档答案一定是「某个面正对你」，玩家转到六个面之一就能撞上，这是**故意留的脚手架**。进阶档起混入 45° 和等距朝向，穷举空间从 6 涨到 40+，穷举比推理更慢，玩法自然从「扫」切换到「想」。
- **允许解数 S**：有多少个候选朝向能达到通过阈值。S 越大越容易撞对。这是本作最灵敏的难度旋钮，比方块数灵敏得多。
- **格点大小固定 3×3×3**，不升到 4×4×4。4×4×4 会让剪影细节掉到 64×64 位图的可辨识极限以下，同时手机上看不清。这是砍掉的东西。

## 7. 旋转控制规格

### 7.1 旋转数学（避免万向锁与「转过头方向就反了」）

用**增量四元数左乘**，不要用欧拉角累加：

```
每帧：
  qYaw   = quatFromAxisAngle(worldUp(0,1,0),      dx * SENS)
  qPitch = quatFromAxisAngle(cameraRight(1,0,0),  dy * SENS)
  qDelta = qYaw * qPitch
  objectQuat = normalize(qDelta * objectQuat)     // 左乘 = 绕屏幕轴转
```

- 水平拖 → 绕**世界 Y 轴**（不是物体自身 Y 轴），保证「往右拖，物体永远往右转」，这是 trackball 手感的关键。
- 垂直拖 → 绕**相机右轴**（屏幕水平轴）。
- 不提供绕视线轴（roll）的直接操作。**代价**：某些答案朝向需要画面内旋转才能达到 —— 通过 yaw+pitch 的组合是可达的（SO(3) 上 yaw/pitch 两轴生成整个旋转群），但对玩家不直观。**处理**：入门/基础档的出题过滤会把「仅差一个画面内旋转」的朝向也算进解数 S（见 §8.3），所以新手不会卡在 roll 上；进阶档起 roll 差异成为正当难度。

### 7.2 手感参数

| 参数 | 值 | 区间 | 说明 |
| --- | --- | --- | --- |
| `dragSensitivity` | **0.45 度/px** | 0.30–0.60 | 540 宽下拖过半屏（270px）= 121°。低于 0.3 手指不够用，高于 0.6 微调做不了 |
| `maxAngularSpeed` | **720 度/秒** | 480–900 | 上限，防止甩一下就看不清 |
| `inertiaSampleWindow` | **80 ms** | 60–120 | 抬手时取最近 80ms 的平均角速度作为初速 |
| `inertiaDamping` | **每秒衰减到 8%** | 5%–15% | `v *= pow(0.08, dt)`。抬手后约 0.9 秒基本停住 |
| `inertiaCutoff` | **12 度/秒** | 8–20 | 低于此速直接归零，避免永远微动导致判定采样永远不触发 |
| `snapEnterAngle` | **10 度** | 6–14 | 与任一解朝向角距小于它就开始磁性吸附 |
| `snapMaxTorque` | **90 度/秒** | 60–140 | 吸附角速度上限 |
| `snapLockAngle` | **1.5 度** | 1–3 | 小于它直接硬 snap 到解朝向并停住 |
| `keyStepAngle` | **15 度** | 10–20 | Shift+方向键的单次步进 |
| `keyHoldSpeed` | **90 度/秒** | 60–140 | 按住方向键的连续旋转速度 |

### 7.3 磁性吸附曲线

```
θ = 当前朝向与最近解朝向的角距（四元数点积转角度）
若 θ ≤ snapLockAngle              → 硬 snap，角速度清零
若 θ ≤ snapEnterAngle 且 未按下指针 → 施加朝向该解的角速度
                                     ω = snapMaxTorque * (1 - θ/snapEnterAngle)^0.6
否则                                → 不干预
```

**「未按下指针」这个条件是本作最重要的一条手感设计。** 玩家手指还在屏幕上时抢他的控制权，会让人觉得「这东西不听我的」，比没有吸附还糟。吸附只在松手后接管，玩家感受到的是「我松手，它自己吸上去了」的爽感。

指数 0.6（而不是线性）让吸附在远端更明显、近端更柔和，避免最后 1 度弹跳。

### 7.4 输入映射

**触屏**

- 旋转区内单指按下并拖动 = 旋转。抬起进入惯性。
- **只接受第一根有效手指**，忽略额外触点（多指会产生冲突的 dx/dy）。
- 「定形」按钮独立命中，按钮上的按下不会触发旋转。
- 禁止页面滚动 / 缩放 / 系统手势（容器已有 `touch-none`）。
- 指针离开画布、`pointercancel`、失焦 → 立即结束当前拖拽并进入惯性。

**键鼠**

- 鼠标左键按住拖动 = 旋转，与触屏完全一致。
- 方向键 / WASD 按住 = 连续旋转（90 度/秒）。
- Shift + 方向键 = 单次 15 度步进（微调用）。
- **空格 = 定形**。
- P / ESC = 暂停。
- 不给「15 度步进 = 全部按键穷举」留后门的理由见 §9.3。

**不做的输入**：双击定形（误触率高）、双指缩放、陀螺仪。

## 8. 判定规格

### 8.1 IoU 计算

- 目标位图 `M_target`、当前位图 `M_current`，均为 64×64 二值。
- `IoU = |M_target ∩ M_current| / |M_target ∪ M_current|`。
- **通过阈值 `IOU_PASS = 0.92`**。区间 0.88–0.95。
  - 低于 0.88：玩家会在明显没对齐时通过，顿悟感消失。
  - 高于 0.95：64×64 的像素量化误差本身就能吃掉 3–4 个点，会出现「看起来完全重合但判不过」，这是最伤的一类挫败。
- 因为有 `snapLockAngle` 硬 snap，正确解在 snap 之后 IoU 恒等于 1.0，阈值只影响「没吸附上就按定形」的边缘情况。

### 8.2 采样时机（性能与反制的双重设计）

当前剪影通过 **64×64 WebGLRenderTarget** 渲染纯黑剪影 + `readRenderTargetPixels` 读回。这是一次 GPU→CPU 同步读，会打断渲染管线，**绝不能每帧做**。

采样条件（三条全满足）：

1. 指针**未按下**；
2. 角速度 < **25 度/秒**（`sampleStillThreshold`）；
3. 距上次采样 ≥ **200 ms**（`sampleThrottleMs`）。

例外：玩家按「定形」时**强制立即采样一次**，无视节流，保证判定用的是当下这一帧。

这个节流不只是性能优化，它同时是 §9.2 的反制手段：**你必须停下来才能拿到读数**。

### 8.3 目标位图的生成

目标位图不走 GPU。在出题时用 **CPU 解析光栅化**生成：把 N 个单位方块的 8 个顶点做正交投影，每个方块得到一个凸多边形（矩形或六边形），扫描线填充进 64×64 位图后取并集。N ≤ 9、朝向池 ≤ 40 个，总计 360 次凸多边形填充，耗时在毫秒级。**出题阶段绝不用 GPU 读回**（40 次同步读会明显卡顿）。

「解数 S」也用这套 CPU 光栅化统计：对朝向池里每个朝向算剪影，与答案剪影 IoU ≥ 0.92 的计为一个解。

入门/基础档统计解数时，**把 4 个画面内 90° 旋转也算作同一个解的变体并各自计数**，这样 S 会偏大、题目偏易，正好对应新手还不会做 roll 的现实。

### 8.4 「定形」交互

- 按钮常态为暗色描边；IoU ≥ 0.55 后随 IoU 线性提亮；IoU ≥ 0.85 后开始 2Hz 脉冲。
- 按下 → 强制采样 → 判定。
- **判对**：进入成功反馈（§10），0.6 秒后出下一题。
- **判错**：-3 秒、红闪、按钮进入 **1.2 秒冷却**（环形进度条）。冷却期间空格和点击都无效。
- 冷却的作用是让「连点定形扫描」的期望收益变成负数：扫一圈 40 个朝向需要 40 × (1.2s + 3s罚时) ≈ 168 秒，远超一整局时间。

### 8.5 渐进反馈映射

| IoU | 反馈 |
| --- | --- |
| < 0.55 | 无任何提示（`glowFloor = 0.55`） |
| 0.55 → 0.92 | 对照框边缘辉光强度线性 0 → 1；提示音基频 440Hz → 880Hz 线性映射；定形按钮亮度同步 |
| ≥ 0.92（未按定形） | 辉光满、按钮脉冲，但**不自动通过** —— 必须玩家自己按 |

`glowFloor = 0.55` 的下限很关键：给得太早（比如 0.2）会让整局变成「盯着光条爬山」，空间推理被绕过。0.55 意味着你已经差不多对上了才会得到确认，它的作用是**消除「我到底对没对上」的模糊焦虑**，而不是替你找答案。

**为什么不自动通过**：自动通过会让乱转成为最优解，整个玩法塌掉。主动确认这一下，既是反制，也是这个游戏的高潮时刻 —— 你要敢下判断。

## 9. 退化打法与反制

| # | 退化打法 | 反制 |
| --- | --- | --- |
| 1 | 疯狂乱转，等它自己判过 | 判定只在主动按「定形」时发生；判错 -3 秒 + 1.2 秒冷却 |
| 2 | 不推理，靠辉光/音高做梯度爬山 | 辉光下限 0.55 + 只在**静止**（角速度<25°/s）时更新 + 200ms 节流。想读一个梯度点就得停 0.2 秒，扫一片区域的成本远高于直接看懂。**承认它是一种合法的低效解法**，由时间压力自然淘汰；禅意模式不淘汰它，但禅意模式记录的正是每题用时 |
| 3 | 六面穷举（把每个面依次转过来试） | 入门/基础档**故意允许**，它是新手的学习脚手架；进阶档起答案朝向池混入 45° 与等距朝向，穷举空间从 6 涨到 40+，穷举变得比推理慢 |
| 4 | Shift+方向键 15° 步进做机械穷举 | 15° 步进覆盖整个 SO(3) 需要数千步；且步进不绕过定形确认的冷却与罚时。不构成威胁，保留它是为了微调手感 |
| 5 | 靠记忆而非空间推理（题目重复） | 题目全程程序化生成；生成器维护本局已用形状的**规范化哈希集合**（对 24 个轴对齐旋转取字典序最小的格点编码），同一形状一局内不重复；且新题答案剪影与上一题答案剪影 IoU 必须 < 0.8 |
| 6 | 存在「万能视角」：先转到等距视角就一定能看懂结构 | 这是**正当技巧，不封杀**（它正是熟练度的体现）。但要保证等距朝向在答案池中占比 ≤ 10%，否则「转到等距再微调」会退化成通用解法 |
| 7 | 对称形状导致多解，玩家瞎按也能中 | 多解不是 bug 而是显式难度旋钮（解数 S）。大师档强制 S == 1 |
| 8 | 退化剪影：接近实心矩形，任何角度都像 | 生成器过滤：剪影填充率 > 0.90 且外接矩形长宽比 ∈ [0.85, 1.18] → 丢弃重抽 |
| 9 | 卡死在一题上，把时间耗光（挫败退出） | **防卡阀门**：单题耗时 25 秒后，对照框内淡入一条辅助线标出目标剪影的最长边方向；再过 15 秒（累计 40 秒）闪一次 0.4 秒的正确朝向预览。触发过阀门的题目**解题奖励减半**，代价明确 |
| 10 | 甩手指制造超高角速度绕过采样/看穿判定 | 角速度硬上限 720°/s；采样条件本来就要求静止，高速期间根本不采样 |
| 11 | 切后台挂机保时间 | `visibilitychange` 失焦即暂停计时，回来显示「点击继续」，需一次新的按下才恢复 |
| 12 | 在按钮上按下后拖出去再松手 | 按钮采用「按下与抬起都在按钮内」才生效；拖出即取消，不消耗冷却 |

## 10. 反馈设计（产品层，具体表现由 ART.md 定义）

| 事件 | 视觉 | 音效 | 震动/时间 |
| --- | --- | --- | --- |
| 拖动中 | 方块棱边高光随角速度增强；对照框内当前剪影实时跟随 | 无 | — |
| 松手惯性 | 自然减速，无额外特效 | 无 | — |
| 进入辉光区（IoU≥0.55） | 对照框边缘辉光 0→1；重合区白色面积可见增长 | 正弦音 440→880Hz，随 IoU 变化，仅静止时更新 | — |

**反馈可读性底线**：玩家按下定形失败时，必须能立刻看出「差在哪」—— 所以失败时对照框要保持显示当前剪影与目标的差集（红色高亮不重合区域）1.0 秒，而不是直接清空。这一条是本作反馈设计里最重要的，没有它玩家会觉得「判定莫名其妙」。

## 11. 出题算法

### 11.1 形状生成（面连通 polycube）

```
1. 在 3×3×3 格点中随机取一个起点（偏向中心，中心 27 格按到中心的距离加权）
2. 重复 N-1 次：从当前集合的所有面邻居（在格点范围内、未选中）里随机取一个加入
3. 得到一个 N 块的面连通 polycube
```

**必须面连通**（不能只角连通）：视觉上是一个整体，没有悬空块，剪影可读性高得多，也符合「一团方块」的直觉。

### 11.2 答案朝向池（最多 40 个）

- 24 个轴对齐旋转（立方体旋转群）
- 8 个「绕世界 Y 轴 45°」变体（4 个 yaw45 × 2 个 pitch 档）
- 4 个等距朝向（俯角 arctan(1/√2) ≈ 35.26°，4 个方位）
- 4 个备用（棱心朝向）

各档按 §6 的表取子集。

### 11.3 过滤（每条不过就重抽）

1. 剪影填充率 ∈ [0.12, 0.55]（占 64×64 画布）。太小看不清，太大没信息。
2. 剪影填充率 > 0.90 且外接矩形近正方形 → 丢弃（退化实心块）。
3. 剪影必须 4-连通，孔洞数 ≤ 档位上限。
4. 解数 S 落在档位区间内。
5. 与上一题答案剪影 IoU < 0.80。
6. 形状规范化哈希不在本局已用集合中。

### 11.4 兜底（这一条给 playtest_critic）

- 重抽上限 **40 次**。40 次仍失败 → 把 S 区间放宽一档并重试最多 20 次；仍失败 → 使用一组**内置的 6 个手工种子形状**之一。
- **绝不允许出现无上限的 while 循环。** 出题卡死会直接冻结主线程，是这个玩法最致命的一类 bug。
- 出题必须在一帧内完成（预算 8ms）。若实测超时，改为在上一题成功反馈的 600ms 间隙里预生成下一题。

### 11.5 持久化

`localStorage['shadowcast-best']` 存一个 JSON 字符串：

```
{ "relaySolved": 12, "relayAvgMs": 9400, "zenAvgMs": 11200 }
```

读取失败 / JSON 解析异常 / 字段类型不对 → 全部回退到 0，不影响开局。

## 12. 上手引导（前 10 秒，零文字教程）

**第 1 题是固定的手工种子，不随机。**

- 形状：4 块 L 形（3 块一行 + 1 块垂直），答案朝向是正面轴向，目标剪影是一个一眼能认的「L」。
- **开局朝向被摆在距离答案 35° 的位置** —— 明显不对，但差得不多，随手拖两下就能进辉光区。
- 进游戏后 0.3 秒起，物体自动缓慢转 12° 再转回来（1.2 秒的一次往返），同时对照框里当前剪影跟着动。**这个自动演示就是全部教学**：它同时说明了三件事 —— 这东西会转、影子跟着变、要和灰色目标重合。玩家第一次触摸时立即中断演示。
- 玩家随手一拖 → 进辉光区 → 定形按钮开始脉冲 → 按钮的脉冲就是「该按我了」的教学。
- 第 2 题起进入随机生成。
- 全局唯一的文案是按钮上的「定形」两个字、HUD 的时间数字和题号。菜单页额外有一行「转动方块，让影子对上」。

**失败结算页的归因**：结算不展示抽象数据，展示「你解开了 N 题 / 平均每题 X 秒 / 失误 M 次」。失误次数是玩家自己能改进的唯一指标，把它放在显眼位置。

## 13. 状态流程

### 菜单

- 展示标题、一个缓慢自转的示例方块团（活的封面）、最高纪录、模式选择（接力 / 禅意）。
- 单击任一模式立即开始，不做二次确认。

### 游戏中

- HUD：题号、时间条、当前纪录。
- 暂停：P / ESC / 右上角按钮。暂停时**隐藏 3D 物体和对照框**（防止暂停当作无限思考时间）。
- 失焦自动暂停，恢复需一次新的按下。

### 结算

- 触发：接力时间归零 / 玩家在禅意模式主动结束。
- 展示：解题数、总用时、平均每题、最快一题、失误次数、是否新纪录。
- 「再来一局」按钮。**必须等待一次新的按下事件**，防止结算点击穿透成为新一局的第一次拖拽。

### 重开

必须重置：题号、计时器、当前形状、目标位图、已用形状哈希集合、旋转四元数、角速度、惯性采样窗口、定形冷却、防卡阀门计时器、辉光状态、音频振荡器。保留最高纪录。

## 14. WebGL / 资源回收（playtest_critic 检查清单）

这是本作**最高优先级的技术风险**：Three.js 不像 Phaser 有 `destroy(true)` 一把梭，漏回收的表现是「反复进出游戏页 8–16 次后页面变白」，而且在开发期很难注意到。

`startGame` 返回的对象在 `destroy()` 时**必须逐条完成**：

1. `cancelAnimationFrame(rafHandle)`，并把 handle 置空；设置 `disposed = true` 让循环体提前 return。
2. 移除**全部** DOM 监听：`pointerdown` / `pointermove` / `pointerup` / `pointercancel` / `pointerleave`、`keydown` / `keyup`、`visibilitychange`、`resize`、`contextmenu`。监听注册时就用具名函数保存引用，不要用匿名箭头函数。
3. 遍历 scene：每个 `Mesh` 的 `geometry.dispose()`、`material.dispose()`（材质是数组时逐个）、材质上挂的 `map/alphaMap` 等 `texture.dispose()`。
4. **所有方块共用同一个 `BoxGeometry` 实例**，它只能 dispose 一次 —— 遍历 dispose 时要去重（用 Set 收集后统一 dispose），既不能漏也不能重复。
5. 两个 `WebGLRenderTarget`（64×64 剪影 RT，以及若实现了对照框的离屏 RT）各自 `.dispose()`。
6. `renderer.dispose()` → `renderer.forceContextLoss()` → `renderer.domElement.remove()` → 置空引用。**三步缺一不可**，只调 `dispose()` 不会释放 context。
7. 关闭音频：所有还在响的 `OscillatorNode.stop()` + `disconnect()`，`GainNode.disconnect()`，最后 `audioContext.close()`。
8. 清掉所有 `setTimeout` / `setInterval`（定形冷却、滴答音、成功反馈延时、防卡阀门）。
9. `destroy()` **必须幂等**：重复调用不抛错、不重复 dispose。`PhaserCanvas` 的卸载路径存在异步竞态，可能调用两次。

**验收方法**：在 `/shadowcast` 与首页之间连续来回 20 次，Console 不得出现 `Too many active WebGL contexts` 或 `WebGL context lost`；DevTools 内存快照中 `WebGLRenderer` 实例数为 0，`Detached HTMLCanvasElement` 数为 0。

## 15. 对项目契约的改动

`src/games/types.ts` 当前写死返回 `Phaser.Game`，需要放宽为结构化类型：

```ts
export type GameInstance = { destroy: (removeCanvas?: boolean) => void };
export type GameModule = { startGame: (parent: HTMLElement) => GameInstance };
```

- `Phaser.Game` 天然满足这个结构，**现有三款游戏一行都不用改**。
- `PhaserCanvas.tsx` 里的 `destroy(true)` 调用点保持不变，`shadowcast` 的 `destroy(removeCanvas?)` 忽略参数即可。
- `PhaserCanvas` 的组件名不改（它本来就是「通用挂载容器」的角色），只放宽类型注释。是否改名留给实现方判断，不属于本作范围。

**明确禁止：本作不与 Phaser 共存。** 不要为了复用 Phaser 的 UI 而在同一页同时跑 Three 和 Phaser 两个渲染循环 —— 那是掉帧的直接来源，而掉帧是用户已经在抱怨的问题。HUD 用一层覆盖在 canvas 上的 DOM（或第二个 2D canvas）实现。

Three.js 只 import 需要的模块（`WebGLRenderer` / `Scene` / `OrthographicCamera` / `BoxGeometry` / `MeshBasicMaterial` / `Quaternion` / `WebGLRenderTarget`），tree-shake 后 gzip 约 150KB 量级，且只在进入 `/shadowcast` 路由时动态加载，首页与另外三款零影响。

## 17. MVP 验收标准

**功能**

- 触屏单指与鼠标拖拽的旋转手感一致；键盘可完成全部操作（旋转 + 定形 + 暂停）。
- 任意朝向下方块团都不被视口裁切（正交半宽 2.9 生效）。
- 出题器在 1000 次连续生成中：不卡死、不超时（单次 < 8ms）、不产生违反 §11.3 任一过滤条件的题目、不重复形状。
- 解数 S 的统计与实际可通过的朝向数一致（用离线脚本抽查 100 题）。
- 判定采样确实被节流（加计数器验证：一局内 GPU 读回次数远小于帧数）。
- 定形冷却、罚时、防卡阀门按 §8/§9 执行。
- 暂停 / 失焦 / 恢复 / 结算 / 重开不残留定时器、监听器、旋转状态或旧题目。
- §14 的 20 次进出测试全部通过。
- `pnpm lint` 与 `pnpm build` 通过。

**体验（「手感对了」的判据）**

- 拖动跟手，物体转动方向与手指方向永远一致，不出现「转过头之后方向反了」。
- 松手后的惯性衰减自然，不会长时间微动导致判定采样迟迟不触发。
- 磁性吸附只在松手后发生，玩家在按住时**感受不到任何被抢控制权**。
- 从「看起来对了」到「按下定形通过」之间没有意外失败（阈值 + 吸附共同保证）。
- 定形失败时玩家能在 1 秒内看出差在哪（差集高亮）。
- 新玩家在 10 秒内不看任何文字就完成第 1 题。
- 中低端手机（如 4 年前的中端安卓）稳定 60fps；单帧 3D 绘制调用数 < 15（方块共享 geometry + material，可用 InstancedMesh 但非必需）。

### 削减版（MVP−，约 850 行）

如果要压到常规体量，按以下顺序砍：

1. **砍禅意模式**（-40 行）—— 但这是性价比最高的模式，最后才砍。
2. **砍防卡阀门**（-60 行）—— 代价是新手可能卡死在一题上直到超时，挫败风险上升。建议保留第一级辅助线，砍掉第二级预览。
3. **砍 45° 与等距朝向池**，答案只用 24 个轴对齐朝向（-50 行，出题过滤也简化）—— 代价是「六面穷举」在全难度都有效，天花板明显变低。
4. **HUD 用 DOM 而非自绘 canvas**（-80 行）—— 已经是本方案的选择，不是削减项。
5. **砍结算页的详细统计**，只留解题数和纪录（-40 行）。

### 明确不做的东西（范围控制）

- **不做手工关卡编辑**。所有题目程序化生成。
- **不做 4×4×4 格点**。剪影细节会掉到 64×64 与手机屏幕的可辨识极限以下。
- **不做缩放 / 平移操作**。会引入尺度与位置不变性，多解爆炸，判定失去意义。
- **不做真实阴影**（ShadowMap）。剪影用第二个正交相机渲纯色，零光照。
- **不做多光源、材质、贴图、后处理、抗锯齿以外的任何画面增强**。用户已在抱怨掉帧。
- **不做骨骼动画、模型加载、GLTF**。仓库里那两个 .blend 与本作无关。
- **不做三档难度选择菜单**（理由见 §4.3）。
- **不做每日挑战 / 固定种子**（可作为后续扩展，需要日期种子和 UI，MVP 外）。
- **不做联网排行、成就系统、道具**。
- **不与 Phaser 共存**。

## 19. 后续可选扩展（不属于 MVP）

- **每日一题**：用日期做种子生成 5 道固定题，全局玩家看到同一套（无需服务端，种子即共识）。
- **限步模式**：给定旋转「角度预算」，转过的总角度有上限，逼玩家规划路径而不是乱转 —— 这是最能加深策略性的一个方向。
- **双投影模式**：给两个方向的目标剪影（正面 + 侧面），必须同时满足。难度大幅上升，但机制增量极小（多算一个 RT），是天花板最高的扩展。
- **彩色方块**：剪影带颜色分区，比对时颜色也要对上。
- 更多形状族（带孔洞的、非连通的）。

扩展优先级原则：**优先增加空间推理的维度，而不是增加数值或内容量**。「双投影」和「限步」都符合这条；「更多形状族」只是内容量，优先级最低。
