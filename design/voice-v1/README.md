## 统一布局

以 390×844 CSS 像素为基准，适配 360–480px 与 safe-area。图中状态栏是设备示意，不能重复画到 PWA DOM。粉色云端街机头图、奶白内容底、珊瑚主按钮、淡紫辅助色，绿色耳机方块作为原创主题。正文使用深灰，不把浅粉用于正文。左右边距16px，卡片间距12px，圆角20px，主操作高度48px，触摸区域至少44px。图中文字实现时全部用 DOM，房间资料/头像/人数/聊天取真实数据。装饰和卡片插画独立切出或重新生成，禁止整页截图当背景。

大厅两列房卡；顶部“好友房 / 房间邀请”，底部四导航仅用于大厅及邀请列表。房间内无全局导航，以麦位、聊天、语音控制和输入框为主。聊天区独立滚动，键盘弹起时输入框保持可见。8麦为默认示例，真实 maxSpeakers 可8–32，maxMembers可至64；超过8麦用可滚动麦位区域，人数不可由创建者自行选择。大字模式允许房卡改为单列。

## 页面及行为

| 画面 | 主要行为 | 对应已有接口/状态 |
| --- | --- | --- |
| 大厅 | 仅展示服务端返回的可见房间，点卡加入；创建入口 | GET /api/voice/rooms，POST rooms/:id/join |
| 创建 | 房名1–40字，直接创建语音房，无关联游戏选择；好友/私密可见，上麦审批默认开启 | POST rooms：title, visibility, requiresMicApproval；不传 gameSlug |
| 房间 | 按micSeat排座，展示房主/管理员徽标，空座不是直接授权；文字聊天保留 | GET rooms/:id、messages，POST messages、rtc-token |
| 邀请列表 | 接受时先加入成功再导航；婉拒立即更新，重复点提交禁用 | GET invites，PATCH invites/:id decline；join携inviteId |
| 邀请好友 | 用真实好友列表，一次邀请一个人，成功后标已邀请 | POST rooms/:id/invites targetUid |
| 上麦审批 | 管理角色看请求队列，批准/拒绝以返回状态更新 | PATCH members/:uid approve-mic / reject-mic |
| 房间管理 | 房主编辑标题、游戏、可见性；查看成员和申请；关闭二次确认 | PATCH rooms/:id set-title / set-game / set-visibility / close |
| 成员操作 | 按角色与目标状态裁剪菜单，不是固定展示全部按钮 | PATCH members/:uid：lower-mic、staff-mute、staff-unmute、kick、set/unset-moderator、transfer-owner |
| 权限 | 旁听加入不申请麦克风；主动申请发言时说明并触发真实权限请求 | 浏览器授权 + mic-request，不可只凭客户端授权发布音频 |
| 离房 | 普通离开与关闭房间分开，确认后断开RTC并清理本地麦克风 | POST rooms/:id/leave；房主离开后的继任使用后端结果 |
| 断线 | 区分仅RTC故障与全网断线；明确关闭发送音频能力 | 重取房间/发布权限及RTC票据成功后才恢复 |

## 麦克风状态

1. 旁听：显示“当前仅收听 / 申请上麦”；无需先开麦权限。
2. 等待审批：显示“等待批准 / 取消申请”，使用 release 取消；按钮不可反复发请求。
3. 已批准：取得发布票据且系统授权后才可开麦。初始仍关闭本地麦克风，由用户明确开启。
4. 已上麦：切换“开麦 / 关麦”，旁边提供下麦；说话指示消费真实音量，不固定播放动画。
5. 管理禁麦：显示“已被禁麦”，不能用本地开麦绕过；恢复需服务端允许并重新取得发布权限。
6. 权限拒绝：解释如何在浏览器站点设置开启，保留旁听和文字聊天；不循环弹权限框。
7. RTC断开：关闭音频发送，提示重连；只有HTTP仍可用时才能显示“文字聊天仍可用”。全网断线需禁用提交并明确“网络已断开”。重连不自动开麦。

## 必须随实现处理的状态

大厅加载/无好友房/读取失败；邀请空列表/过期/已拒绝；房间已满/已关闭/被移出；上麦位已满/审批列表已空；发送失败保留文本；创建失败保留表单；举报分类与描述校验；屏蔽与解除屏蔽列表；关闭房间、转让房主、移出成员的确认框。举报、屏蔽入口面向普通成员；管理操作以服务端角色和约束为准。

## 图稿与协议的交付修正

这些约束优先于生成图片的偶发示例：

- 2026-09-10 用户修订：创建语音房无需关联游戏，移除创建页的关联游戏字段，默认名称为“用户名 的语音房”。无关联游戏的大厅及邀请卡片显示“一起聊天”；旧房间已有的关联信息保留。

- 大厅“输入房间码”是待接线设计：当前join要求roomId，不能仅凭6位码调用。开发会话补受鉴权的解析流程或用携roomId的邀请链接，未完成前隐藏此入口。
- 房间ID是UUID，六位roomCode是私密入房凭据；不能把示例“房间ID 123456”硬编码或向所有成员展示。仅房主收到roomCode，其他成员使用合法邀请。
- 邀请列表接口目前只返回有效pending邀请：过期卡片用于当前已打开列表的过期状态，不要求虚构历史邀请。
- 管理页生成图的底部全局导航应去掉，用返回键回到原房间，避免误离房。
- 角色菜单只呈现当前可操作项：已上麦不显示“允许上麦”，已禁麦显示“解除禁麦”；房主转让和管理员任命只在允许的目标上显示。禁麦与移下麦位必须区分。
- 房间关联游戏不是已经组队匹配成功的承诺；游戏启动继续使用现有权威协议。生成图房卡的宣传小字为示例，现有房模型无description字段，实现用真实关联游戏名代替。
- 不增加礼物、打赏、KTV、排行榜、公开热门房、虚假在线数。好友头像用实际账号头像，生成头像仅为样例。

尚未进行实现后的同尺寸截图对照，不能标记为一比一还原验收通过。

- 状态稿的头像数量与4/8示例计数不一致：实现时成员数由真实成员列表得出。RTC断线时移除所有说话光圈和音量波形；图中的残留光圈不属于断线设计。输入框左侧麦克风装饰不表示语音消息功能，应替换为普通文字输入。
