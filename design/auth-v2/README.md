# 登录 / 注册 v2 设计提案

2026-09-10。用户要求重新设计登录注册，不再沿用 pwa-v5 的旧认证页面视觉。

设计稿：`01-login-register-concept.png`。使用内置 image_gen 生成；已实现为独立登录 / 注册页面，运行截图见 `02-login-runtime.png`、`03-register-runtime.png`。

方向：奶白底、珊瑚红主按钮、绿色耳机吉祥物、左对齐标题、明确字段标签和充足留白。登录支持 UID / 用户名及密码；注册保留验证码创建账号、自动分配 UID、随后设置密码的现行流程。

实现时：标题、表单、按钮、验证码及导航必须使用真实 DOM，插画单独制作；验证码图片不能使用稿中 A7K9。需复核 393px 手机宽度下标题换行、键盘和滚动。图中英文装饰文字为概念插画内容，不是必需文案。

## 实现与验证

页面采用 auth-v2.css 隔离样式，避免影响管理页及其他 PWA 场景。标题、字段标签、密码显隐、切换链接、返回按钮和验证码为真实 DOM；原稿复制为 public/assets/game-box/auth-v2/reference.png，通过 CSS 仅取插画与品牌图标区域，不把完整表单作为页面背景。原图未经像素编辑。

Mac Chrome CDP 9335：登录与注册 360×800、393×852、480×900、852×393 均无横向溢出；横屏省略装饰插画并允许纵向滚动。验证码真实加载、登录注册切换与密码显隐通过。截图包含 Next 开发指示器。详情见 validation.json。

lint、生产构建和 diff --check 通过，保留已有 middleware 弃用提示。本轮没有重新创建测试账号或做完整鉴权端到端验收，也未覆盖真机键盘；先前的 UID 注册协议未改动。尚未发布。

## 验证码与修改密码页修订

验证码改为上方图片及刷新按钮，下方独立输入框。实际注册页的四视口几何记录见 stacked-validation.json，截图见 04-register-stacked.png。

“我的 → 修改密码”采用同一奶白 / 珊瑚红视觉：账号摘要、纵向标签和 52px 密码框、双字段显隐、登录影响说明、保存按钮、错误与成功状态。返回时清空未提交密码和错误，保存过程中禁止重复关闭 / 提交。新密码提交前校验最少 8 位及两次一致；仍使用既有 /api/auth/password 和更新票据逻辑。

最新 lint、build、diff --check 通过。修改密码页本轮尚未取得真实登录账号下的实拍，也没有实际改动现有账号密码，不能据构建宣称完整业务验收。

## 首次设置密码页

`/auth?mode=account&next=%2F&setup=1` 已并入 auth v2。页面把开户收尾拆成“保存 UID → 设置密码”两步，显示可复制的登录 UID、带标签的两组密码框和明确的“设置密码并进入”按钮。密码不足 8 位或两次未填写时按钮保持禁用。

运行截图见 `05-account-setup-runtime.png`，四视口结果见 `account-setup-validation.json`。由于注册接口当时处于既有限流窗口，截图通过浏览器对 `/api/auth/me` 的局部拦截使用演示 UID 123456；没有绕过后端、写数据库或提交密码。布局、按钮启用和密码显隐已验证，真实开户提交仍沿用此前已通过的现行协议证据。
